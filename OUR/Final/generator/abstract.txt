Introductory programming courses often lose their first week to software installation, not programming. In UNLV’s introductory C++ course (CS 135) and x86-64 assembly course (CS 218), several hundred students a year must get a compiler or assembler, a linker, a debugger, and an editor working on dozens of different laptops, and students with Apple Silicon Macs often cannot run the course’s 19 GB virtual machine at all. This project packages each course’s exact toolchain and a browser-based Visual Studio Code editor into a Docker container that runs entirely on the student’s own laptop: one 552 MB download, one command, no server, no account, and nothing recorded. Coursework stays in an ordinary folder, so the container can be deleted or updated without touching student files. To test whether that promise holds on the laptops students actually own, one unmodified script performed a student’s first day and four real CS 218 assignments, including a multithreaded program, on four machines: Intel and ARM Linux rented from AWS, Windows 11 rented from Azure, and an M1 Pro MacBook Pro. All four downloaded the identical image and passed every assignment. The editor opened in 0.5 s on Intel chips and 5 to 7 s on ARM chips, where x86-64 code runs through a translator roughly ten times slower but still within seconds. The one limit is the debugger, which the translator cannot support on ARM. That boundary is documented in the student handout, every raw result is public, and a classroom study is planned next.
